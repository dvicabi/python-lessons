# מדריך למורה

בקשו מהציוד ומהצוות להחזיר מידע לכל אולם ולא רק למועמד ראשון.

## הפעלה

מומלץ להתחיל בשיחת תכנון קצרה: מי מקבל מה וממי, ומה צריך להיות הפלט כאשר קלט לא חוקי. אחר כך לתת זמן לעבודה אישית ולבדיקות בזוגות. בסיום מסירה של גרסה משולבת והכנסת דרישת לקוח חדשה.

חלוקה מוצעת: שיעור 1 דרישות ותיאום, שיעורים 2–3 פיתוח אישי, שיעור 4 חיבור ובדיקות, שיעור 5 שינוי דרישה והדגמה. התאימו לקצב הכיתה; המסלול המלא דורש לולאות ורשימות.

## פתרון

[reference.py](reference.py) הוא מימוש אפשרי אחד לכל ששת הרכיבים באותו קובץ. הקוד משתמש ברשימות, תנאים ולולאות, ללא פעולות שהוגדרו מראש. אפשר להריץ אותו ישירות ב-Python.

```bash
python reference.py
python verify.py
```

הסקריפט verify.py בודק תרחישי קבלה מוגדרים. התלמידים נדרשים בנוסף להמציא תרחישים ולהסביר את הממצאים.

## הערכה מתוך 100

- 40 נקודות: מערכת אישית, תקינות והסבר עצמאי של הקוד.
- 25 נקודות: המוצר השלם ובדיקות הקבלה.
- 20 נקודות: תקשורת, תיעוד הסכמות וחיבור עם חברי צוות. נדרש תיעוד קצר מכל תלמיד של חיבור אחד וביקורת קוד אחת.
- 15 נקודות: תכנון ניסויי בדיקה, תיקון תקלה והצגת התוצאה.

אם רכיב של תלמיד אחר חסר, ניתן לבחון את הרכיב האישי עם קלט דמה. ציון האינטגרציה נבדק בנפרד, כך שתלמיד אינו מאבד את כל ציון העבודה בגלל חבר צוות.

## שאלות במהלך הצגה

- תלמיד 1: למה מזהה חוזר נפסל? למה ציוד 0 מותר?
- תלמיד 2: למה קיבולת אינה זמינות? למה לא לבחור מיד אחד?
- תלמיד 3: למה תוספת אינה שלילית? למה צריך לשמור תוספת לכל אולם?
- תלמיד 4: למה מעגלים כלפי מעלה? למה תוספת שונה בין אולמות?
- תלמיד 5: למה האולם הזול אינו בהכרח הזול בסך הכול? מה קורה בשוויון?
- תלמיד 6: למה מעתיקים? מה נשמר בכשל צוות?

הפתרון ציבורי במאגר. עדיף לשתף בתחילת העבודה רק את דף הפרויקט והמשימות האישיות.

## הסבב השני

בדיקת המורה כוללת הרצה נוספת על המצב המעודכן, ללא איפוס משאבים. יש לדרוש מהצוות גם תרחיש חוזר משלו.
