# שדה תעופה: מרכז תיאום יציאת טיסה מדומה

במסך מרכז הבקרה מוצגת בקשה להוציא טיסה. כל מחלקה מחזיקה חלק מהמידע: הזמנה, נוסעים, מטען, שער וזמן. אף מחלקה לא רשאית לאשר את הטיסה לבדה.

## מה הלקוח מבקש?

הדגימו תהליך תיאום מדומה של שש מערכות, שבו מוקצה שער פנוי רק אם כל הרכיבים אישרו את הבקשה. במקרה דחייה השערים נשארים ללא שינוי.

## כללי המוצר

זהו משחק תיאום בדוי, ללא שימוש בתעופה אמיתית. כל המספרים הם יחידות משחק.

טיסה נבחרת לפי מזהה ברשימה. מספר הנוסעים שנבדקו חייב להיות שווה למספר המוזמנים ולהיות לכל היותר הקיבולת.

כל תיק במשקל דמה 1–20, מספר תיקים לכל היותר מספר נוסעים, וסכום המשקלים לכל היותר פי 15 ממספר הנוסעים.

בוחרים את השער הפנוי הקטן ביותר המתאים למספר הנוסעים; בשוויון הראשון. זמן מוכנות מדומה הוא now + מספר נוסעים + משקל כולל // 10. מוכנות עד זמן הטיסה מותרת.

סדר הדחיות: FLIGHT, PASSENGERS, BAGS, GATE, TIME. רק אישור OK מעדכן תפוסה.

## סדר העבודה

1. פתחו יחד את [מבנה המערכת](system_architecture.md) והסכימו מי אחראי על כל רכיב.

2. קראו את [הסכם הממשקים](team_contract.md). קיימו שיחת תיאום לפני שמתחילים לכתוב קוד.

3. כל תלמיד פותח את הקובץ האישי שלו ועובד לפי הרמה שנלמדה.

4. בדקו את [תרחישי הקבלה](test_scenarios.md) וחברו את הרכיבים לפי [הנחיות האינטגרציה](integration.md).

5. הציגו מוצר עובד. כל תלמיד מסביר מה הוא קיבל, מה הוא מסר ומה השתנה בעקבות התיאום.
