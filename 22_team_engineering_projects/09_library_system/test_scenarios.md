# תרחישי קבלה

העתיקו את נתוני ההתחלה מקובץ `starter/scenario.py`. בכל ניסוי הפעילו את הקוד מחדש, עם השינויים בלבד שמפורטים להלן.

## תרחיש 1: השאלה חוקית

עותק 0 שמור לאחר, נבחר 2.

השתמשו בנתוני ההתחלה ללא שינוי.

**תוצאה נדרשת בסוף:**

```text
result = "OK"
copy_index = 2
due = 24
holders_after = [0, 0, 101, 0]
reserved_after = [102, 0, 0, 0]
limits_after = [1, 1]
used_after = [50, 51]
```

לפני ההרצה, כל בעל רכיב כותב מה הוא צופה שיקרה אצלו ומה הוא אמור להעביר לרכיב אחר. לאחר הרצה תעדו את הפלט בפועל ואת הסיבה לכל הבדל.

## ניסוי עצמאי של הצוות

המציאו שני תרחישים נוספים: אחד בגבול החוקי, ואחד שבו רכיב בודד נכשל למרות שכל הרכיבים האחרים חוקיים.

כתבו מראש את התוצאה הרצויה. הכינו טבלת מעקב לפי בחירתכם. הוכיחו שלא בוצע שינוי חלקי במצב כאשר העסקה או הבקשה נדחתה.

## סבב שני: מצב שנשמר בין בקשות

בקשה חדשה של אותו קורא לספר זהה: העותק הקודם כבר הושאל ולכן נבחר עותק אחר.

הריצו תחילה את התרחיש המקורי. אין לאתחל שוב את נתוני ההתחלה. העבירו את המצב הסופי למשתני הקלט של ההרצה השנייה בהתאם למיפוי הבא:

```python
holders = holders_after
reserved = reserved_after
limits = limits_after
used_ids = used_after
loan_id = 52
```

הריצו שוב את כל ששת הרכיבים. התוצאה הנדרשת לאחר הסבב השני:

```text
result = "OK"
copy_index = 1
due = 17
holders_after = [0, 101, 101, 0]
limits_after = [0, 1]
used_after = [50, 51, 52]
```

בדקו שאין הקצאה כפולה או הפחתה נוספת כאשר הבקשה נדחית. כל בעל רכיב מסביר מה נקרא מחדש ומה נשמר בין ההרצות.
