# ספרייה עירונית: השאלת ספרים בין סניפים

קורא מבקש ספר. עותקים נמצאים בסניפים שונים, חלקם מושאלים, וחלקם שמורים לקוראים אחרים. הצוות מפתח מוצר שמאפשר השאלה רק אם הקורא והעותק עומדים בכל הדרישות.

## מה הלקוח מבקש?

בחרו עותק מתאים ועדכנו יחד את מצב העותק, מכסת הקורא ויומן מזהי ההשאלה. הריצו בקשה חוזרת על המצב החדש.

## כללי המוצר

נתוני דמה בלבד. מזהים ייחודיים. קורא פעיל עם מכסת השאלות חיובית; מזהה השאלה חיובי וחדש.

מותר לבחור עותק של הספר המבוקש שאינו מושאל (holder=0), ואינו שמור לאחר (reserved=0 או מזהה הקורא).

בחרו לפי מרחק הסניף הנמוך ביותר, ואז אינדקס ראשון. השאלה בסניף מרוחק (מרחק מעל 3) נמשכת 7 ימים, אחרת 14. תאריך החזרה = היום + משך.

סדר דחיות MEMBER, BOOK, COPY, LIMIT. רק אישור משנה מצב; רשימות הקלט באורכים תואמים.

## סדר העבודה

1. פתחו יחד את [מבנה המערכת](system_architecture.md) והסכימו מי אחראי על כל רכיב.

2. קראו את [הסכם הממשקים](team_contract.md). קיימו שיחת תיאום לפני שמתחילים לכתוב קוד.

3. כל תלמיד פותח את הקובץ האישי שלו ועובד לפי הרמה שנלמדה.

4. בדקו את [תרחישי הקבלה](test_scenarios.md) וחברו את הרכיבים לפי [הנחיות האינטגרציה](integration.md).

5. הציגו מוצר עובד. כל תלמיד מסביר מה הוא קיבל, מה הוא מסר ומה השתנה בעקבות התיאום.
