# מדפסת תלת ממד: האם אפשר לסיים את ההדפסה?

**משך מומלץ:** 45–60 דקות  
**כלים שכבר למדנו:** for, break, חישוב מצטבר, סף, פונקציה, קלט תקין  
**תפקידכם:** צוות הנדסת תוכנה. עליכם להבין את הבעיה, לנתח מערכת קיימת, לבדוק אותה ולפתח גרסה משופרת.

## א. הסיפור והבעיה

במעבדת בית הספר מדפיסים חלקים לרובוט. ההדפסה מתבצעת שכבה אחר שכבה. אם החומר נגמר באמצע שכבה, החלק עלול להיפסל. במקום להתחיל כל שכבה בלי בדיקה, יש לתכנן תוכנה שמנהלת מלאי ומחליטה מתי לעצור.

כמות החומר נמדדת ביחידות דמיוניות. כל שכבה צורכת את הכמות ברשימה ועוד יחידת פסולת אחת. חובה להשאיר לפחות 2 יחידות רזרבה לאחר שכבה. המדפסת יכולה לעצור רק בין שכבות בסימולציה. אין כאן נוסחה אמיתית להדפסת תלת ממד.

## ב. לפני המחשב: חשבו כמו מהנדסים

ענו במחברת, לפני כתיבת קוד. הגדירו קלט, פלט, מידע שנשמר בין פעולות וכלל שהמערכת חייבת לשמור עליו תמיד.

1. מה ההבדל בין חומר שנצרך לבין חומר שמותר להשתמש בו?
2. למה צריך לדעת את עלות השכבה הבאה לפני שמתחילים?
3. איזה מידע כדאי להציג למפעיל בעת עצירה כדי שיוכל להחליט מה לעשות?

## ג. קריאת קוד ומעקב ידני

הקוד הבא הוא אב-טיפוס קיים שקיבלתם מצוות אחר. **אל תריצו אותו עדיין.** עברו שורה אחר שורה וחשבו מה קורה בפועל.

```python
def trace(layers):
    remaining = 13
    printed = 0
    reserve = 2
    for index, layer in enumerate(layers, 1):
        cost = layer + 1
        if remaining - cost < reserve:
            print(index, "PAUSED", cost, remaining, printed)
            break
        remaining -= cost
        printed += 1
        print(index, "PRINTED", cost, remaining, printed)
    print("FINAL", remaining, printed)

trace([3, 5, 4, 6, 2])
```

1. השלימו את הטבלה; בעמודת המצב/הערך יש לרשום את הערך **בסוף** האיטרציה, אלא אם כתוב "לפני".
2. סמנו במפורש צעד שלא מתבצע בגלל עצירה. אם יש שורת פלט לאחר הלולאה, כתבו גם אותה.
3. הוסיפו טבלת מעקב מפורטת לאיטרציה אחת שיש בה החלטה משמעותית: שורת קוד, משתנה שהשתנה, ערך קודם, ערך חדש, נימוק.
4. כתבו את הפלט המדויק, כולל סדר השורות. רק לאחר מכן הריצו והשוו.

## ד. מעקב נוסף: אותו קוד, קלט אחר

החליפו רק את הקריאה האחרונה לפונקציה ב-`trace([3, 6, 1])`. שוב אל תריצו לפני שהשלמתם את הטבלה.

| שכבה | layer | cost | חומר לפני | החלטה | חומר אחרי | printed |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 3 |   |   |   |   |   |
| 2 | 6 |   |   |   |   |   |
| 3 | 1 |   |   |   |   |   |

כתבו את הפלט המדויק. השוו בין שני הקלטים: באיזה שלב התנהגות המערכת משתנה ומדוע? הוסיפו קלט שלישי משלכם שיגרום למסלול החלטה שונה או שיבדוק ערך גבול.

## ה. שאלות חשיבה וביקורת קוד

1. מה משמעות השורה FINAL? האם היא בהכרח מעידה שההדפסה הצליחה?
2. למה משתמשים ב-`<` ולא ב-`<=` בבדיקת הרזרבה? השתמשו בקלט השני.
3. מה יקרה אם נעדכן remaining לפני התנאי ונעצור ב-break ללא ביטול השינוי?
4. השוו בדיקה לכל שכבה בנפרד לבדיקה מראש של סך כל החומר. באיזה מצב כדאי לבחור כל גישה?

**תקלה מכוונת:** החליפו את התנאי ב-`if remaining < cost:`. מצאו רשימה קצרה (למשל שכבה בעלות 12 מתוך 13) שמוכיחה שהקוד מפר את דרישת הרזרבה. הסבירו איך לתקן.

כתבו מה הדרישה שנפגעת, מה הקלט הקטן ביותר שמדגים זאת, מה התקבל בפועל ומה היה אמור להתקבל.

## ו. עכשיו אתם המפתחים

כתבו `plan_print(layers, stock, reserve)` שמחזירה `(printed, remaining, status, next_index)`. index הוא מספר שכבה החל מ-1; במקרה של DONE החזירו None. מלאי ורזרבה שליליים, או מלאי קטן מהרזרבה בהתחלה, מחזירים ERROR ו-next_index=0. כל עובי חייב להיות שלם חיובי; אם שכבה לא תקינה מגיעה לעיבוד, עצרו ERROR בלי לצרוך חומר ודווחו על מספרה. בדקו רזרבה לפני ביצוע כל שכבה. שכבה שדורשת יותר מהמלאי הזמין גורמת PAUSED. בקלט ריק עם מלאי תקין DONE. אין לשנות את הרשימה.

**דרך עבודה:**
- נסחו לפחות שלושה כללים שהמערכת חייבת לשמור עליהם. הגדירו מה קורה בקלט ריק, בקלט חריג ובערך גבול.
- כתבו פסאודו-קוד או תרשים זרימה לפני הפתרון. ציינו מתי משתנה המצב, מתי הנתונים מתעדכנים ומתי עוצרים.
- כתבו פונקציה עצמאית עם שמות משתנים בעלי משמעות. אל תשנו את הקוד הקיים; הוא משמש להשוואה.
- הוסיפו קריאות לפונקציה עם `print`. אין צורך ב-input בשלב הזה כדי שכל הצוותים יוכלו להריץ אותם מקרי בדיקה. מי שמסיים יכול להוסיף ממשק input בנפרד.

## ז. בדיקות קבלה

לפני הרצה, חשבו מדוע כל מקרה חשוב. אחרי ההרצה מלאו את התוצאה בפועל והחליטו אם הבדיקה עברה.

| # | קלט | פלט צפוי (ערך מוחזר) | פלט בפועל | עבר / נכשל |
| --- | --- | --- | --- | --- |
| 1 | `plan_print([3,5,4,6,2], 13, 2)` | `(2, 3, "PAUSED", 3)` | | |
| 2 | `plan_print([3,6], 13, 2)` | `(2, 2, "DONE", None)` | | |
| 3 | `plan_print([2,0,3], 10, 2)` | `(1, 7, "ERROR", 2)` | | |
| 4 | `plan_print([], 2, 2)` | `(0, 2, "DONE", None)` | | |
| 5 | `plan_print([1], 1, 2)` | `(0, 1, "ERROR", 0)` | | |
| 6 | `plan_print([1,2], 7, 2)` | `(2, 2, "DONE", None)` | | |

הוסיפו לפחות שלוש בדיקות משלכם: מקרה גבול, מקרה תקלה ומקרה שמוכיח כלל מרכזי. אם בדיקה נכשלת, שמרו את הקלט לפני תיקון, תקנו והפעילו את כל הבדיקות שוב.

## ח. שינוי דרישות מהלקוח

קיבלתם דרישה להמשיך אחרי החלפת גליל החומר, בלי להדפיס שוב שכבות מוצלחות. תכננו נתונים שנשמרים בעת עצירה, דרך לבדיקת שכבה הבאה ותרחיש שבו מותר להמשיך. השוו שמירת מספר השכבה לעומת מחיקת שכבות מהרשימה.

1. כתבו מה השתנה בדרישות ומה לא.
2. ציינו אילו משתנים, תנאים ופונקציות יושפעו מהשינוי.
3. הציעו פסאודו-קוד. אם נשאר זמן, ממשו את ההרחבה בקובץ נפרד והדגימו פלט.
4. כתבו בדיקה אחת שמוכיחה שגרסת הבסיס לא נשברה ובדיקה אחת לדרישה החדשה.
