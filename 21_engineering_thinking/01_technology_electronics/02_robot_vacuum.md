**משך מומלץ:** 60–75 דקות  
**כלים שכבר למדנו:** לולאות, רשימות, tuples, תנאים, חברות ברשימה, אלגוריתם ניווט  
**תפקידכם:** צוות הנדסת תוכנה. עליכם להבין את הבעיה, לנתח מערכת קיימת, לבדוק אותה ולפתח גרסה משופרת.

## א. הסיפור והבעיה

חברת רובוטיקה בוחנת שואב אבק בחדר מדומה. השואב נע בין משבצות, עלול להיתקל ברהיט, וכל ניסיון תנועה צורך סוללה. בעל הבית רוצה לדעת כמה שטח באמת נוקה, ולא רק כמה צעדים הרובוט עשה.

חדר בגודל 3×3, שורות ועמודות ממוספרות 0–2. נקודת התחלה (0,0), מכשול (0,2). R ימינה, L שמאלה, D למטה, U למעלה. בניסוי הראשון כל ניסיון תנועה עולה 2 יחידות, גם אם חסום. משבצת ההתחלה נחשבת נקייה. החדר אינו מפה של רובוט אמיתי.

## ב. לפני המחשב: חשבו כמו מהנדסים

ענו במחברת, לפני כתיבת קוד. הגדירו קלט, פלט, מידע שנשמר בין פעולות וכלל שהמערכת חייבת לשמור עליו תמיד.

1. ציירו רשת של תשע משבצות וסמנו התחלה ומכשול. אילו משבצות ניתן להגיע אליהן?
2. מדוע משתנה שמונה צעדים אינו מספיק כדי לדעת כמה משבצות נוקו?
3. הגדירו את ההבדל בין מיקום נוכחי, מסלול ורשימת משבצות ייחודיות.

## ג. קריאת קוד ומעקב ידני

הקוד הבא הוא אב-טיפוס קיים שקיבלתם מצוות אחר. **אל תריצו אותו עדיין.** עברו שורה אחר שורה וחשבו מה קורה בפועל.

```python
def trace(commands):
    moves = {"R": (0, 1), "L": (0, -1),
             "D": (1, 0), "U": (-1, 0)}
    position = (0, 0)
    visited = [position]
    battery = 10
    for step, command in enumerate(commands, 1):
        if battery < 2:
            print(step, "STOP", position, battery, len(visited))
            break
        dr, dc = moves[command]
        candidate = (position[0] + dr, position[1] + dc)
        battery -= 2
        if (0 <= candidate[0] < 3
                and 0 <= candidate[1] < 3
                and candidate != (0, 2)):
            position = candidate
            status = "MOVED"
            if position not in visited:
                visited.append(position)
        else:
            status = "BLOCKED"
        print(step, status, position, battery, len(visited))

trace(["R", "R", "D", "L", "D", "R", "U"])
```

1. השלימו את הטבלה; בעמודת המצב/הערך יש לרשום את הערך **בסוף** האיטרציה, אלא אם כתוב "לפני".
2. סמנו במפורש צעד שלא מתבצע בגלל עצירה. אם יש שורת פלט לאחר הלולאה, כתבו גם אותה.
3. הוסיפו טבלת מעקב מפורטת לאיטרציה אחת שיש בה החלטה משמעותית: שורת קוד, משתנה שהשתנה, ערך קודם, ערך חדש, נימוק.
4. כתבו את הפלט המדויק, כולל סדר השורות. רק לאחר מכן הריצו והשוו.

## ד. מעקב נוסף: אותו קוד, קלט אחר

החליפו רק את הקריאה האחרונה לפונקציה ב-`trace(["L", "D", "U", "R", "L"])`. שוב אל תריצו לפני שהשלמתם את הטבלה.

| צעד | פקודה | מיקום מועמד | status | position | battery | מספר משבצות |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | L |   |   |   |   |   |
| 2 | D |   |   |   |   |   |
| 3 | U |   |   |   |   |   |
| 4 | R |   |   |   |   |   |

כתבו את הפלט המדויק. השוו בין שני הקלטים: באיזה שלב התנהגות המערכת משתנה ומדוע? הוסיפו קלט שלישי משלכם שיגרום למסלול החלטה שונה או שיבדוק ערך גבול.

## ה. שאלות חשיבה וביקורת קוד

1. מה קורה לצעד 7 בקלט הראשון? האם הוא נקרא בכלל?
2. מה ההבדל בין אורך המסלול ובין len(visited) בצעד 3 של הקלט השני?
3. באיזה צעד הוספת אותו מיקום פעמיים הייתה גורמת לדוח ניקיון מוטעה?
4. האם אפשר לנקות את כל שמונה המשבצות עם 10 יחידות סוללה? תנו חסם עליון למספר המשבצות החדשות והסבירו.

**תקלה מכוונת:** הסירו בדמיון את `position not in visited`. מצאו צעד בקלט השני שבו הכיסוי המדווח גדל ללא ניקוי משבצת חדשה. כתבו תנאי מתוקן.

כתבו מה הדרישה שנפגעת, מה הקלט הקטן ביותר שמדגים זאת, מה התקבל בפועל ומה היה אמור להתקבל.

## ו. עכשיו אתם המפתחים

כתבו `vacuum(commands, battery)` עם אותה מפה והתחלה. בתוכנית החדשה תנועה מוצלחת עולה 2 יחידות וניסיון חסום עולה 1. מותר להתחיל ניסיון רק כשיש לפחות 2 יחידות, גם אם מתברר שהוא חסום. פקודה לא מוכרת מחזירה ERROR לפני כל שינוי; בדקו אותה לפני בדיקת הסוללה. סוללה התחלתית שלילית או מעל 10 מחזירה ERROR ללא תנועה. החזירו `(position, battery, visited, status)`, כאשר visited היא רשימה לפי סדר גילוי. סטטוס COMPLETE אם כל הפקודות טופלו, LOW אם פקודה תקינה לא בוצעה מחוסר סוללה. בקלט ריק COMPLETE. כל הערכים שלמים.

**דרך עבודה:**
- נסחו לפחות שלושה כללים שהמערכת חייבת לשמור עליהם. הגדירו מה קורה בקלט ריק, בקלט חריג ובערך גבול.
- כתבו פסאודו-קוד או תרשים זרימה לפני הפתרון. ציינו מתי משתנה המצב, מתי הנתונים מתעדכנים ומתי עוצרים.
- כתבו פונקציה עצמאית עם שמות משתנים בעלי משמעות. אל תשנו את הקוד הקיים; הוא משמש להשוואה.
- הוסיפו קריאות לפונקציה עם `print`. אין צורך ב-input בשלב הזה כדי שכל הצוותים יוכלו להריץ אותם מקרי בדיקה. מי שמסיים יכול להוסיף ממשק input בנפרד.

## ז. בדיקות קבלה

לפני הרצה, חשבו מדוע כל מקרה חשוב. אחרי ההרצה מלאו את התוצאה בפועל והחליטו אם הבדיקה עברה.

| # | קלט | פלט צפוי (ערך מוחזר) | פלט בפועל | עבר / נכשל |
| --- | --- | --- | --- | --- |
| 1 | `vacuum(["R","R","D","L","D","R","U"], 10)` | `((2, 0), 1, [(0, 0),(0, 1),(1, 1),(1, 0),(2, 0)], "LOW")` | | |
| 2 | `vacuum(["L","D","U"], 5)` | `((0, 0), 0, [(0, 0),(1, 0)], "COMPLETE")` | | |
| 3 | `vacuum(["X"], 0)` | `((0, 0), 0, [(0, 0)], "ERROR")` | | |
| 4 | `vacuum([], 1)` | `((0, 0), 1, [(0, 0)], "COMPLETE")` | | |
| 5 | `vacuum(["R"], 1)` | `((0, 0), 1, [(0, 0)], "LOW")` | | |
| 6 | `vacuum(["D"], 11)` | `((0, 0), 11, [(0, 0)], "ERROR")` | | |

הוסיפו לפחות שלוש בדיקות משלכם: מקרה גבול, מקרה תקלה ומקרה שמוכיח כלל מרכזי. אם בדיקה נכשלת, שמרו את הקלט לפני תיקון, תקנו והפעילו את כל הבדיקות שוב.

## ח. שינוי דרישות מהלקוח

קבעו תחנת טעינה ב-(0,0). הציעו דרך לתכנן חזרה לתחנה לפני שהסוללה נגמרת, גם אם יש מכשול. השוו מרחק מנהטן למסלול חוקי על רשת. אין צורך לממש אלגוריתם חיפוש מלא; הגדירו דוגמה שבה מסלול ישיר חסום ותכננו פתרון.

1. כתבו מה השתנה בדרישות ומה לא.
2. ציינו אילו משתנים, תנאים ופונקציות יושפעו מהשינוי.
3. הציעו פסאודו-קוד. אם נשאר זמן, ממשו את ההרחבה בקובץ נפרד והדגימו פלט.
4. כתבו בדיקה אחת שמוכיחה שגרסת הבסיס לא נשברה ובדיקה אחת לדרישה החדשה.
