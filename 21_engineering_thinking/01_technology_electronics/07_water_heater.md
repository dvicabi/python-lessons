# דוד חשמל מדומה: איך מונעים הפעלה וכיבוי ללא הפסקה?

**משך מומלץ:** 60–75 דקות  
**כלים שכבר למדנו:** תנאים, מצב בוליאני, לולאות, היסטרזיס, זיכרון תקלה  
**תפקידכם:** צוות הנדסת תוכנה. עליכם להבין את הבעיה, לנתח מערכת קיימת, לבדוק אותה ולפתח גרסה משופרת.

## א. הסיפור והבעיה

חברה בוחנת בקר חימום מדומה. התוכנה הישנה מחליפה מצב בכל פעם שהמדידה זזה מעט סביב סף אחד. בגרסה החדשה יש סף הפעלה וסף כיבוי נפרדים, ויש מנגנון נעילת תקלה.

המספרים והספים מומצאים לתרגול בלבד: מתחת או שווה 45 מפעילים, מעל או שווה 50 מכבים, ובטווח שביניהם שומרים את המצב הקודם. מדידה חוקית 0–80; חריגה נועלת FAULT ומפסיקה חימום. לא מדובר בהמלצת טמפרטורה או בבקר לציוד ממשי; אין לבצע חיבור לחשמל.

## ב. לפני המחשב: חשבו כמו מהנדסים

ענו במחברת, לפני כתיבת קוד. הגדירו קלט, פלט, מידע שנשמר בין פעולות וכלל שהמערכת חייבת לשמור עליו תמיד.

1. למה סף יחיד גורם למעבר מצב תכוף כשמדידות מתנדנדות סביבו?
2. מה ההבדל בין כיבוי רגיל לבין נעילת תקלה?
3. שרטטו מצבים OFF, ON, FAULT; אילו מעברים מותרים ללא איפוס?

## ג. קריאת קוד ומעקב ידני

הקוד הבא הוא אב-טיפוס קיים שקיבלתם מצוות אחר. **אל תריצו אותו עדיין.** עברו שורה אחר שורה וחשבו מה קורה בפועל.

```python
def trace(readings):
    heater = False
    fault = False
    active = 0
    for step, value in enumerate(readings, 1):
        if not 0 <= value <= 80:
            fault = True
        if fault:
            heater = False
        elif value <= 45:
            heater = True
        elif value >= 50:
            heater = False

        if heater:
            active += 1
        print(step, value, heater, fault, active)

trace([42,45,49,50,48,44,43,99,42])
```

1. השלימו את הטבלה; בעמודת המצב/הערך יש לרשום את הערך **בסוף** האיטרציה, אלא אם כתוב "לפני".
2. סמנו במפורש צעד שלא מתבצע בגלל עצירה. אם יש שורת פלט לאחר הלולאה, כתבו גם אותה.
3. הוסיפו טבלת מעקב מפורטת לאיטרציה אחת שיש בה החלטה משמעותית: שורת קוד, משתנה שהשתנה, ערך קודם, ערך חדש, נימוק.
4. כתבו את הפלט המדויק, כולל סדר השורות. רק לאחר מכן הריצו והשוו.

## ה. שאלות חשיבה וביקורת קוד

1. מדוע במדידות 3 ו-5 של הקלט הראשון הטמפרטורות דומות אך מצב הבקר שונה?
2. למה active לא יורד כשהחימום מכובה? איזה מידע הוא מייצג?
3. מה יקרה אם fault יוגדר False בראש כל סיבוב? עקבו אחרי מדידה 9.
4. השוו את הקלט השני לבקר שמפעיל בכל פעם שערך נמוך מ-48 ומכבה אחרת. ספרו את מספר מעברי המצב בכל גרסה.

**תקלה מכוונת:** החליפו בדמיון את `elif value <= 45:` ב-`if value <= 45:` נפרד. אחרי תקלה, מדידה תקינה ונמוכה עלולה להדליק את החימום. הראו זאת במדידה 9 ותקנו את הקדימות.

כתבו מה הדרישה שנפגעת, מה הקלט הקטן ביותר שמדגים זאת, מה התקבל בפועל ומה היה אמור להתקבל.

## ו. עכשיו אתם המפתחים

כתבו `heater_control(events, max_run)` עם אותם ספים. אירוע הוא מספר שלם או המחרוזת RESET. max_run חיובי, אחרת החזירו `(False, True, 0, 0)`. RESET מאפס fault, heater ואת מונה הרצף run, אינו מדידה ואינו משנה active. מדידה לא חוקית נועלת תקלה. במצב FAULT אין חימום עד RESET. גם אם הדרישה להמשיך חימום נשמרת, אם run כבר שווה max_run, נעלו תקלה וכבו לפני שמוסיפים מדידה פעילה נוספת. אם החימום כבוי בכל מדידה, אפסו run. החזירו `(heater, fault, active, run)`; active הוא סך כל המדידות שבהן החימום נותר פעיל, run הוא מספר המדידות הפעילות ברצף. בקלט ריק מצב OFF.

**דרך עבודה:**
- נסחו לפחות שלושה כללים שהמערכת חייבת לשמור עליהם. הגדירו מה קורה בקלט ריק, בקלט חריג ובערך גבול.
- כתבו פסאודו-קוד או תרשים זרימה לפני הפתרון. ציינו מתי משתנה המצב, מתי הנתונים מתעדכנים ומתי עוצרים.
- כתבו פונקציה עצמאית עם שמות משתנים בעלי משמעות. אל תשנו את הקוד הקיים; הוא משמש להשוואה.
- הוסיפו קריאות לפונקציה עם `print`. אין צורך ב-input בשלב הזה כדי שכל הצוותים יוכלו להריץ אותם מקרי בדיקה. מי שמסיים יכול להוסיף ממשק input בנפרד.

## ח. שינוי דרישות מהלקוח

תכננו תיעוד אירועים שמבחין בין SENSOR_FAULT, TIME_LIMIT, NORMAL_OFF ו-RESET. הגדירו איך להציג לבודק מה קרה, אפילו כשהמצב הנוכחי שוב תקין. כתבו שלוש בדיקות מעבר סף ושתי בדיקות איפוס.

1. כתבו מה השתנה בדרישות ומה לא.
2. ציינו אילו משתנים, תנאים ופונקציות יושפעו מהשינוי.
3. הציעו פסאודו-קוד. אם נשאר זמן, ממשו את ההרחבה בקובץ נפרד והדגימו פלט.
4. כתבו בדיקה אחת שמוכיחה שגרסת הבסיס לא נשברה ובדיקה אחת לדרישה החדשה.
